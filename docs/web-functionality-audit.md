# LucidWrite 功能修复与上线验收

本次针对 Vercel 云端网站，保留现有布局和样式。基线提交为 `9b8ca772e1283953b2128f0f6eb8c9db3bdc6e03`。本地 CLI/插件的多智能体流程不属于本次改造；云端写作通过所选模型和可选联网检索完成。

## 已修复

| 范围 | 问题与修复 |
| --- | --- |
| 文章存储 | 修正 PostgREST upsert 的冲突键；数据库失败不再返回保存成功；项目初稿创建失败会回滚本次新建项目。 |
| 编辑格式 | 保留原始 Markdown；编辑后保存标题、粗体、链接、列表、代码、引用和表格；清空编辑器不再恢复旧稿。 |
| 自动保存 | 本机恢复副本、串行自动保存、离开前提示；版本冲突返回 409，避免旧页面覆盖新文章；可以重新打开项目比较恢复副本。 |
| 写作流程 | 无正文不推进阶段；报告不覆盖正文；用户在 AI 运行期间编辑或切换项目时，迟到结果不会覆盖当前稿件；重跑和重复点击有状态保护。 |
| 进度恢复 | 对话、当前阶段、核查/评分结果、已应用任务持久化；刷新后可恢复任务结果和项目进度。 |
| 云端文件 | 文件树、文件/目录引用、项目切换连接实际数据；引用失败保留输入，过期请求不把内容插入另一个项目。 |
| 设置与风格 | 个人模型、API Key、风格样本实际保存；空 Key 输入保留原配置；响应只返回是否已配置；可重新打开风格设置。 |
| 模型调用 | 接入 OpenAI 兼容协议、Anthropic Messages、Gemini；正确拼接 URL；空输出、截断、限流、余额、网络等错误明确反馈；个人 Key 不发送到服务端通用代理。 |
| 长任务 | Edge 响应先发送 JSON 空白心跳，模型完成并保存后返回任务 JSON；客户端超时覆盖读取完整响应。 |
| 事实核查 | 有 Tavily 或 Firecrawl 配置时检索证据；无配置、无结果或检索失败时，由服务端明确标注未完成外部事实验证。模型报告仍需核对证据。 |
| 登录与注册 | 并发请求共享一次令牌刷新；保留密码首尾字符；修复注册确认跳转、中文输入法误发送、重复提交及开发绕过入口。 |
| 数据隔离 | 新设置、任务及文章父项目归属由 RLS 约束；失效会话不继续写入；退出登录清空工作区和敏感输入。 |
| 构建 | 独立网页类型检查和静态构建入口；修复原项目 import.meta 类型错误；新增网页 CI。 |

## 验证

- `bun run test:web`：35 项测试，覆盖浏览器脚本、真实 API handler（上游使用模拟服务）、模型协议和 PostgreSQL 权限。
- PostgreSQL 使用 PGlite 执行原 schema 和增量迁移，验证迁移可重复、现有文章保留、不同用户的设置/任务/文章隔离。
- 原生 Tabbit 浏览器在本地模拟服务环境走通：登录 → 跳过风格 → 创建项目 → 选题 → 大纲 → 初稿 → 精修 → 事实核查 → 评分 → 终稿 → 刷新重新打开。
- `npm run build:web`、`bun run typecheck`、`bun run build` 已通过。
- 全仓测试曾运行 1181 项：1180 通过，1 项 CLI 在线版本检查碰到默认 5 秒测试上限（其网络超时也为 5 秒）。单独以 `--timeout 15000` 重跑该文件，8 项全部通过。本次未改动该 CLI 测试。
- 上述本地验证不等于生产 Supabase、真实邮件、真实模型余额和真实检索的验收。

## 上线顺序

1. 在项目 Supabase SQL Editor 执行 `supabase/migrations/202609070001_web_functionality.sql`。这是增量迁移，新增 `projects.state`、`user_settings`、`writing_tasks` 和权限策略，不删除文章。已有项目不要重新执行整份基础 schema。
2. 检查 Vercel 环境已有 `SUPABASE_URL`、`SUPABASE_ANON_KEY`。写作需要至少一种模型 Key，可使用个人设置或服务端环境变量（见 `.env.example`）。联网核查需要 Tavily/Firecrawl。网页不需要 service-role key。
3. 配置 Supabase Auth 允许正式站点的 `/app` 注册确认回跳地址；如验收预览部署，也需要相应的精确预览地址。
4. 在修复分支的 Vercel 预览中，用测试账号进行真实验收，尤其是旧文章保存、刷新恢复、风格/Key 设置和模型请求。
5. 验收后合并 main，等待生产部署 Ready，再重复关键流程。

**数据库迁移完成前不要把此版本提升到生产。** 新接口依赖新增表和字段。当前生产升级待 Supabase 已登录会话和真实测试账号完成验收。

## 生产验收清单

- 注册确认邮件进入 /app；登录错误反馈正确；令牌过期后仍可保存。
- 打开已有文章，修改后保存并刷新，Markdown 内容一致。
- 建立独立验收项目，走通全部写作阶段、终稿保存及重新打开。
- 配置有效模型后真实生成；错误 Key 有明确错误，不丢失正文；慢请求保持连接。
- 未配置搜索时明确显示“未完成外部事实验证”；配置后检查报告链接确有依据。
- 在两个页面编辑同一草稿，旧版本保存得到冲突，本机副本可恢复。
- 第二个测试账号无法读取第一个账号的项目、设置和任务。

## 运行本地验收环境

```sh
bun install --frozen-lockfile
bun run test:web
bun run tests/web/fixture-server.ts
```

浏览器打开 `http://127.0.0.1:3917/app`。模拟账号为 `writer@example.test` / `writing-test-123`，第二账号为 `other@example.test` / 同一测试密码。服务仅监听 127.0.0.1，数据仅存在内存；这些是模拟凭据，不能登录生产。停止并重启会清空本地模拟数据。

回退应用代码可使用 Vercel 上一部署；增量表和字段保留即可兼容旧版，回退时不要删除用户新数据。

参考：[PostgREST upsert](https://postgrest.org/en/stable/references/api/tables_views.html#upsert)、[Vercel Edge 响应时限](https://vercel.com/docs/functions/runtimes/edge)。
