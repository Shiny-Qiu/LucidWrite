## 新环境上线顺序

1. 在项目 Supabase SQL Editor 执行 `supabase/migrations/202609070001_web_functionality.sql`。这是增量迁移，新增 `projects.state`、`user_settings`、`writing_tasks` 和权限策略，不删除文章。已有项目不要重新执行整份基础 schema。
2. 检查 Vercel 环境已有 `SUPABASE_URL`、`SUPABASE_ANON_KEY`。写作需要至少一种模型 Key，可使用个人设置或服务端环境变量（见 `.env.example`）。联网核查需要 Tavily/Firecrawl。网页不需要 service-role key。
3. 配置 Supabase Auth 允许正式站点的 `/app` 注册确认回跳地址；如验收预览部署，也需要相应的精确预览地址。
4. 在修复分支的 Vercel 预览中完成构建和接口检查；登录态验收须使用该域名下的测试会话。
5. 合并 main，等待生产部署 Ready，在正式域名的测试会话中重复关键流程。

**数据库迁移完成前不要把此版本提升到生产。** 新接口依赖新增表和字段。

用户选择 V4 Pro 后，个人设置已保存为 `deepseek-v4-pro`，网页默认值、设置提示和环境变量示例同步更新。云端会把历史 `deepseek-chat`、`deepseek-reasoner` 配置解析为 V4 Pro，设置页显示与实际请求一致；显式选择的 V4 Flash 或其他供应商保持原选择。新增测试验证默认模型、历史名称迁移、服务器凭据继续可用，以及思考响应只取最终回答。

官方已发布 V4 Pro 和 V4 Flash，并公告旧模型名停用：[DeepSeek 更新日志](https://api-docs.deepseek.com/updates/)、[当前模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)。V4 默认开启思考；当前网页使用普通多轮对话，不提交工具调用，按官方协议只将最终回答传入后续轮次：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

V4 Pro 已通过正式网站真实请求验证：返回写作建议，原稿和当前阶段保持不变，重开设置仍为 `deepseek-v4-pro`。

## 文件树打开文章

- 点击云端项目名称：打开该项目的工作稿及对话，同时展开目录。点击名称左侧箭头只展开或收起目录。
- 点击 `draft.md`：在中间编辑工作稿；同一项目切回工作稿时保留当前编辑。
- 点击 `final.md`：读取实际保存的终稿，在中间只读预览，显示文件路径和“返回工作稿”。预览与工作稿使用独立内容，预览期间不启动 AI 修改或覆盖终稿。
- 右侧输入 `@`：继续选择文件或目录作为对话引用。

新增五项自动测试覆盖文件点击与项目对话恢复、目录箭头行为、不同内容的终稿与工作稿隔离、文件不存在，以及退出登录后到达的旧预览响应。

侧栏布局修复在隔离的本地浏览器中使用长项目名称检查：正常缩放下的 286px 侧栏，以及 150% 缩放触发的 230px 侧栏均完整显示账号、设置、退出、刷新、项目名称和文件类型。此项为 CSS 修复，使用实际截图和网页构建验证，未新增只检查样式字面值的测试。

## 运行本地验收环境

```sh
bun install --frozen-lockfile
bun run test:web
bun run tests/web/fixture-server.ts
```

浏览器打开 `http://127.0.0.1:3917/app`。模拟账号为 `writer@example.test` / `writing-test-123`，第二账号为 `other@example.test` / 同一测试密码。服务仅监听 127.0.0.1，数据仅存在内存；这些是模拟凭据，不能登录生产。停止并重启会清空本地模拟数据。

回退应用代码可使用 Vercel 上一部署；增量表和字段保留即可兼容旧版，回退时不要删除用户新数据。

参考：[PostgREST upsert](https://postgrest.org/en/stable/references/api/tables_views.html#upsert)、[Vercel Edge 响应时限](https://vercel.com/docs/functions/runtimes/edge)。
